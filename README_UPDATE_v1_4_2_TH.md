# Love Matcha Sales v1.4.2

อัปเดตจาก v1.4.1 โดยเน้นใช้งานเร็วบนมือถือ และไม่กระทบข้อมูลเดิมใน Firebase

## สิ่งที่อัปเดต

### 1) หน้าลงรายจ่าย
- ย้ายช่องกรอก “รายจ่ายอื่น ๆ” และ “รายจ่ายประจำ” ขึ้นบนสุดก่อนตารางสรุปและตารางรายการ
- ค่าเริ่มต้นเรียงรายจ่ายอื่นจากวันที่ใหม่ไปเก่า และรายจ่ายประจำตามสาขาแล้วตามชื่อ
- เลือกวิธีเรียงแต่ละตารางได้ เช่น วันที่ ชื่อ หรือจำนวนเงิน
- เลือกสลับตำแหน่งตาราง “รายจ่ายอื่น ๆ” กับ “รายจ่ายประจำ” ได้
- การเรียงและสลับตารางเป็นเพียงการแสดงผล ไม่แก้ยอดหรือข้อมูลใน Firebase

### 2) รายการขนมและ OT
- ขนมแต่ละชนิดมีรหัสถาวร ไม่ผูกกับตำแหน่งในตาราง
- ใช้ปุ่ม ↑ ↓ เพื่อสลับลำดับ หรือกด “เรียงชื่อ ก-ฮ” ได้
- เพิ่มชนิดขนมใหม่ได้โดยไม่ทำให้รายการเดิมเลื่อนผิดชนิด
- OT วันที่บันทึกไปแล้วคำนวณจากราคาและเปอร์เซ็นต์ที่บันทึกไว้ในวันนั้น จึงไม่เปลี่ยนย้อนหลังเมื่อเพิ่ม ลบ เปลี่ยนชื่อ หรือสลับลำดับขนม
- รองรับข้อมูลเก่าที่มีเฉพาะชื่อขนม โดยระบบจับคู่ชื่อให้อัตโนมัติ

### 3) ธนาคารและเลขบัญชีพนักงาน
- เพิ่มช่องธนาคารและเลขบัญชีในหน้าค่าตอบแทน
- เมื่อบันทึกค่าตอบแทน ระบบเก็บข้อมูลไว้กับพนักงานและนำขึ้นอัตโนมัติในเดือนถัดไป
- ยังแก้ไขได้ทุกเมื่อ ทั้งจากหน้าค่าตอบแทนและหน้าจัดการผู้ใช้
- บันทึกสำเนาธนาคาร/เลขบัญชีไว้ในค่าตอบแทนของแต่ละเดือน เพื่อให้เอกสารเดือนเก่าอ้างอิงข้อมูลที่บันทึกไว้ในเดือนนั้น
- แสดงธนาคารและเลขบัญชีใน PDF

### 4) PDF ค่าตอบแทน
- ตาราง PDF สิ้นสุดที่ “ยอดที่ต้องโอนปลายเดือน”
- ไม่แสดงประกันสังคมนายจ้าง
- ไม่แสดงต้นทุนรวม หรือต้นทุนรวม+ปกส.
- ประกันสังคมฝ่ายลูกจ้างยังแสดง เพราะเป็นรายการหักที่ใช้คำนวณยอดโอน

### 5) อัปเดตเวอร์ชันและความเร็ว
- อัปเดตเป็น v1.4.2 ทุกหน้าหลัก
- เปลี่ยน service worker เป็นแบบดึงไฟล์โปรแกรมหลักจากเครือข่ายก่อน และเก็บสำรองไว้ใช้เมื่อออฟไลน์
- ล้าง cache ของเวอร์ชันเก่าอัตโนมัติ
- เมื่อ service worker ใหม่เริ่มทำงาน ระบบเปิดหน้าใหม่พร้อมพารามิเตอร์เวอร์ชัน เพื่อให้เครื่องที่เคยเปิด v1.4.1 เปลี่ยนเป็น v1.4.2 เร็วขึ้น
- เพิ่ม query version ให้ app.js, style.css และ manifest ลดปัญหา GitHub Pages หรือเบราว์เซอร์จำไฟล์เก่า

## ความปลอดภัยของข้อมูลเดิม

ชุดอัปเดตนี้ไม่ลบ collection และไม่เปลี่ยน document id เดิมใน Firestore

- `dailySales`, `dailyExpenses`, `dessertOT`, `attendance`, `salaryAdvances`, `ownerExpenses` และ `compensationRecords` เดิมยังอยู่ครบ
- ช่องใหม่เป็น optional field ข้อมูลเก่าที่ไม่มีช่องดังกล่าวยังเปิดได้
- รหัสขนมใหม่ถูกเติมเฉพาะในค่าตั้งค่าและรายการใหม่ ส่วนข้อมูลเก่ายังรองรับผ่านชื่อและราคา/% ที่บันทึกไว้
- การคำนวณ OT เดิมไม่อ้างอิงลำดับของรายการขนม

## วิธีอัปโหลด GitHub Pages

1. สำรองข้อมูล JSON จากหน้า Backup ก่อนอัปเดตหนึ่งครั้ง
2. แตกไฟล์ ZIP
3. เปิด repository เดิมใน GitHub
4. อัปโหลดไฟล์และโฟลเดอร์ทั้งหมดจากโฟลเดอร์ v1.4.2 ทับไฟล์เดิม โดยต้องให้ `index.html` อยู่ที่ root เดิม
5. Commit การเปลี่ยนแปลง
6. รอ GitHub Pages deploy เสร็จ
7. เปิดเว็บและตรวจว่าแสดง `v1.4.2`
8. ถ้าเปิดจากไอคอน PWA เดิม ให้ปิดแอปแล้วเปิดใหม่หนึ่งครั้ง ระบบจะล้าง cache เก่าและโหลดเวอร์ชันใหม่

ไม่ต้องลบ Firebase project ไม่ต้องสร้างฐานข้อมูลใหม่ และไม่ต้อง Restore ข้อมูลเมื่ออัปโหลดทับไฟล์เดิมตามขั้นตอนนี้
